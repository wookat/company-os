# SOP-08 资源缺口降级上线手册

适用：外部资源（域名/备案/支付/API key/账号）未到位时的先行上线。配套 CHARTER §3.7「资源缺口不阻塞」。来源：多个真实项目验证过的降级路径。

## 原则
- 缺什么就降级什么，其余部分照常推进；降级实现必须**可替换**（资源到位后一步切换）。
- 每项降级在汇报中标注：缺口 → 当前降级方案 → 资源到位后的切换步骤。

## 标准降级路径

| 缺口 | 降级方案 | 资源到位后 |
|---|---|---|
| 域名/备案 | Cloudflare tunnel（trycloudflare 临时地址）或 *.pages.dev / *.workers.dev / *.vercel.app 子域先上线给老板与测试用户访问 | 绑定正式域名，301 迁移 |
| 国内备案（服务器在境内） | 先部署到境外免备案节点（Cloudflare/海外 VPS）+ tunnel | 备案通过后迁回并切 DNS |
| 支付（微信/支付宝商户号） | 免费模式先跑 + 「预约付费」意向收集（表单/邮箱）；海外先接 LemonSqueezy/Paddle 等 MoR | 接入正式支付，兑现意向用户 |
| 付费 API key | 免费额度/开源替代/本地模型/mock 桩，接口层做 provider 抽象 | 换 key 即切换，无需改业务代码 |
| 第三方账号（平台/店铺/开发者账号） | 沙箱账号或公开样例数据先验证全流程 | 注入真实账号，重跑验证 |
| 发送/触达渠道（邮件/短信） | 写入待发队列 + 预览界面，人工/延后发送 | 配置渠道后自动放行队列 |

## 汇报格式（并入 SOP-04）
```
【资源缺口】<项> | 降级方案：<当前> | 切换成本：<一步/需重测> | 已申请：<日期>
```
