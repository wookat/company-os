# SOP-01 项目全生命周期

适用：所有软件/产品/系统项目。执行者：project-lead（项目负责人）。

## 阶段 0：立项（与 CEO/老板确认后触发）
- 产出「项目一页纸」：目标、范围与非目标、里程碑、组队名单、风险
- 立项后即进入授权自主推进模式（见 CHARTER §3），不再等待批准

## 阶段 1：需求与调研
- market-researcher 按 SOP-02 出调研简报（新产品必做；内部工具可跳过）
- product-manager 产出 PRD：用户故事、验收标准、MVP 边界（非目标必须写明）

## 阶段 2：Spec 与技术方案
- spec-writer 把 PRD 转成工程 spec（接口/数据模型/状态机/边界条件）
- tech-lead 出技术方案与 ADR；关键不确定点先做 PoC 验证

## 阶段 3：计划与分派
- project-lead 把 spec 拆成任务清单：每条任务 = 一个角色一次可独立完成 + 明确验收标准
- 可并行的任务必须并行分派；标注任务间依赖

## 阶段 4：实现
- 工程角色按任务实现，走 TDD（先测试后实现）或至少测试同 PR 提交
- 一切变更走 PR；CI 必须绿；code-reviewer 评审，blocker 不放行
- 原则：YAGNI（不做没要求的）、DRY、不硬编码、不为过测试改测试

## 阶段 5：评审与测试
- qa-engineer 按验收标准做端到端测试，出测试报告
- user-experience-officer 以真实用户身份走查（对外产品必做）
- 对外产品：compliance-counsel 出合规审查报告，"禁止级"问题必须整改

## 阶段 6：交付与验收
- 部署上线（SOP-03）；project-lead 汇总验收包：可运行成果 + 演示录屏/截图 + 需求逐条对照表
- 按 SOP-04 向 CEO/老板汇报交付；汇报后进入维护期，不等待验收回复
