# SOP-01 项目全生命周期

适用：所有软件/产品/系统项目。执行者：project-lead（项目负责人）。

## 阶段 0：立项（与 CEO/老板确认后触发）
- 产出「项目一页纸」：目标、范围与非目标、里程碑、组队名单、风险、**获客/分发/变现计划**（增长与变现前置，CHARTER §6：做不出增长路径的产品不立项）
- 探索型任务（尚未确定方向/找机会）：设定时间盒与子会话预算，产出物落库到仓库或 `org/PROJECTS.md`，到期收敛为立项或关停（CHARTER §6 探索时间盒）
- 重大方向/商业模式/技术选型决策：开多个并行角色会话团队辩论后再定，不独断
- **外部资源清单**：一次性识别需老板提供的资源（支付开通、API key、账号、域名等）并汇报申请；申请后不等待，缺口处用桩/沙箱/降级实现先行，资源到位后替换（CHARTER §3.7）
- 立项后即进入授权自主推进模式（见 CHARTER §3），不再等待批准；开发阶段全闭环自转，不依赖老板任何输入

## 阶段 1：需求与调研
- 从痛点/需求发现出发；market-researcher 按 SOP-02 做**深度调研**：痛点验证、竞品矩阵、用户群体与用户需求（新产品必做；内部工具可精简）；不熟悉领域实例化 domain-expert 咨询
- 赛道已有成熟竞品时按 **SOP-09 复刻竞品与技术反推**：选定标尺竞品，产出「功能对照表」（`docs/competitor-matrix.md`）作为开发任务清单来源，先对齐已验证功能再投差异化
- product-manager 产出 PRD：用户故事、验收标准、MVP 边界（非目标必须写明）

## 阶段 2：Spec 与技术方案
- spec-writer 把 PRD 转成工程 spec（接口/数据模型/状态机/边界条件）
- tech-lead 出技术方案与 ADR；关键不确定点先做 PoC 验证，先打好技术地基与最小可运行骨架，严禁直接开干
- ui-designer + ux-researcher 先完成交互流程与页面设计，前端依据设计稿实现，界面设计不得由工程师独揽

## 阶段 3：计划与分派
- project-lead 把 spec 拆成任务清单：每条任务 = 一个角色一次可独立完成 + 明确验收标准
- 可并行的任务必须并行分派；标注任务间依赖
- 可大规模并行的工作（数据抓取/挖掘、批量内容）组织蜂群：20+ 个并行实例同时开工，效率优先

## 阶段 4：实现
- 工程角色按任务实现，走 TDD（先测试后实现）或至少测试同 PR 提交
- 一切变更走 PR；CI 必须绿；code-reviewer 评审，blocker 不放行；把关通过后由项目负责人**自行合并，不等老板**（CHARTER §3.8）
- 原则：YAGNI（不做没要求的）、DRY、不硬编码、不为过测试改测试

## 阶段 5：评审与测试
四道把关，依次通过才可交付：
1. qa-engineer 按验收标准做端到端测试，出测试报告
2. user-experience-officer 以真实用户身份走查（对外产品必做）
3. 内部交叉测试：非开发本人的工程角色再走一遍主流程
4. 审计保障：compliance-counsel 合规审查（"禁止级"必整改）+ 安全检查（密钥/注入/权限）

## 阶段 6：交付与验收
- 部署上线（SOP-03）——目标是真正上线解决用户痛点的产品，不是 demo/MVP 堆砌
- **竞品对标门槛**：与同类竞品逐项对比，达到或超越可比竞品才有资格提交验收；未达标则回到阶段 4 继续短周期迭代（改进→上线→线上体验测试→修复→回归），不提交
- project-lead 汇总验收包：线上地址 + 演示录屏/截图 + 需求逐条对照表 + 竞品对比结论
- 按 SOP-04 向 CEO/老板汇报交付；汇报后进入维护期，不等待验收回复
- 长期项目：在仓库内建立并持续更新 `docs/handoff-context.md`（模板 `templates/handoff-context.md`），换会话/换负责人时注入，接手即产出
