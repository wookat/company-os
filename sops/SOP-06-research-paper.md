# SOP-06 科研论文项目

适用：以发表论文为目标的研究课题（方法研究、实证研究、基准与审计研究）。执行者：principal-investigator（PI）。

与 SOP-01 的关系：科研项目的交付物是**论文 + 可复现的证据包**，不是上线产品，因此不走 SOP-01 的产品阶段，改走本 SOP。调研部分仍按 SOP-02，汇报仍按 SOP-04。

## 阶段 0：立项
- 产出「课题一页纸」：科学问题、拟主张（claim）、该主张若为真/为假分别意味着什么、可用算力与数据、目标投稿档次
- **先行性核查先于实验**：派 adversarial-reviewer 或 domain-expert 跨领域检索该主张是否已有前人做过。已有则把定位改为「复现 + 扩展」，并写清扩展在哪一点；不得因为"没搜到"就宣称首次
- 组队：PI + experiment-scientist（可多实例）+ paper-author + statistical-reviewer + adversarial-reviewer + venue-strategist

## 阶段 1：可分辨性先于方法
- 在投入任何"做得更好"的实验之前，先测量该基准/该指标上的**噪声地板**：同配置只改随机种子重复训练，得到配对差的标准差
- 由噪声地板计算：给定 seed 预算的可分辨下限（MDE）、宣称某幅度所需的重复次数
- **判据**：若拟宣称的效应量低于可分辨下限，不许排该实验；改为提高可分辨性、换问题，或扩大预算

## 阶段 2：冻结
- 实验开跑前写冻结文件：设计矩阵、每格 n、统计检验、判据、等价性边界、各种可能结果分别允许推出什么结论
- 冻结文件记录哈希与时间戳；任何事后修订必须以「修订记录」形式追加，注明修订时间早于/晚于哪些数据被打分
- **事后不得改判据**；结果出来后改判据等同于伪造

## 阶段 3：执行与验收
- experiment-scientist 执行；每个 run 逐项验收：配置、seed、数据划分 manifest、代码快照、日志、评测输出、完成标记
- 调度器状态不是科学结论；未完成的 run 不计入任何数字
- 不利结果、异常值、失败 run 全部保留；异常值先核查真伪，核查通过的照报

## 阶段 4：双重评审（每轮必做）
1. statistical-reviewer：统计口径、自由度、区间、检验假设、独立性、功效；阴性结果必须附可检出下限
2. adversarial-reviewer：以拒稿为目标攻击本轮最强主张，出书面意见书
- PI 对每条意见三选一处置：接受并改 / 接受但本轮无法解决（写进 limitation）/ 不接受并说明理由

## 阶段 5：并入主稿
- paper-author 并入；**数字由脚本从 artifact 生成，不手打**
- 每轮做陈旧表述全仓扫描：被作废的数字与措辞一处不留
- 主张被推翻时公开撤回并保留撤回记录，不悄悄改写

## 阶段 6：投稿
- venue-strategist 按论文实际类型匹配 scope，逐条核对页数、匿名政策、checklist、时间线
- 提交前跑一遍完整复现：从 artifact 到正文每个数字重算一遍

## 循环
阶段 1–5 为一轮迭代，一轮一个明确的科学问题。PI 每轮做 gate review，不合格退回；达到目标档次的证据强度后才提交老板验收。

## 质量底线（不可越过）
- 不编造数据、不挑 seed、不事后改判据、不删除不利 run
- 不把「不显著」写成「等价」，不把「无证据」写成「有证据表明无效」
- 不宣称未经核查的「首次」
- 每个数字可回溯到脚本与 artifact；不可复算的数字不进正文
